# 王清理

无 root 的 Android 开屏辅助跳过工具，面向小米 15S Pro / Android 17 使用场景。参考 [GKD](https://github.com/gkd-kit/gkd) 的无障碍事件与按应用规则思路，独立实现；不是 GKD 官方版本，也不直接支持 GKD 订阅格式。

## 能力与限制

| 功能 | 当前行为 |
| --- | --- |
| 开屏广告 | 可开启全局保护；单个 APP 的显式开关优先。进入应用后 12 秒内识别小型跳过按钮，一次前台会话最多成功点击一次 |
| 广告弹窗 | 不受开屏时间窗限制；内置匹配明确“关闭广告”等标签，普通关闭/图标须有应用、页面、上下文与按钮的精确规则 |
| 打开应用提示 | 对明确“是否打开其他应用”等提示，点击同界面的小型取消按钮 |
| 广告跳转后返回 | 默认关闭；手工指定来源→目标，在来源开屏窗口内、最近 3 秒见到广告标记时尝试一次返回 |
| 按 APP 统计 | 今日、累计、开屏/弹窗/提示/返回分类、最近记录、每日 CSV 导出；统计的是系统接受的操作，非视觉确认拦截 |
| 临时诊断 | 手动开始两分钟内存计数，记录包名和失败阶段，最多32个包；不保存页面正文、截图，可查看并复制报告 |
| 本地规则 | JSON v1，可约束包名、页面、文字、资源 ID、上下文；不执行脚本、不联网拉取 |
| 后台与开机 | 服务由系统绑定，不依赖首页存活；可选开机通知、提供电池与自启动设置指引 |

无障碍不能全面阻断其他 APP 的 `startActivity`、读取传感器或广告网络请求。摇一摇可能已导致目标页面短暂打开；只有满足明确规则才尝试返回。无访问节点的自绘/视频广告可能无法处理。厂商清理和强行停止后不能保证自恢复。美团、淘宝、哔哩哔哩在应用列表优先显示，但本项目没有声称其所有版本和广告都已适配。

详细依据及小米说明见 [安卓权限与限制](docs/ANDROID-LIMITS.md)，本轮实际阅读的 GitHub 源文件与实现取舍见 [GKD 源码核对记录](docs/GKD-REFERENCE.md)。

## 安装与首次配置

1. 下载仓库 `deliverables/Wang-Cleaner-1.03-debug.apk` 并安装；这是调试签名测试版本，适合侧载验证。
2. 打开王清理，阅读无障碍用途说明，在系统无障碍列表启用王清理。若 Android 提示受限设置，在应用详情中按系统提示允许；菜单位置随 HyperOS 变化。
3. 在首页开启“保护所有应用”，或在“应用”中逐个开启。全局开关默认关闭以保留升级前的选择；某个 APP 曾显式关闭的功能仍保持关闭，可在应用页重新开启。系统设置、常见权限授权与安装器、可识别的桌面和当前输入法等排除在自动操作之外；不保证识别所有厂商自定义组件。
4. 在系统里允许自启动、后台运行，电池策略设为无限制，并在最近任务中锁定王清理。
5. 重启后在“设置”检查实际服务连接。系统强行停止后需手动打开并重新检查。
6. “设置 → 管理广告跳转返回组合”中可添加来源与目标包名。请先只配置确实遇到的广告跳转，正常支付、登录和购物链接同样可能跳转，规则无法判断你的真实意图。

常见包名：美团 `com.sankuai.meituan`、淘宝 `com.taobao.taobao`、哔哩哔哩 `tv.danmaku.bili`。以手机内实际安装包名为准，分身/工作资料空间需分别确认。

## 权限与功耗

必需权限为用户手动开启的无障碍；可选通知用于开机检查提醒。没有联网、悬浮窗、全盘存储、使用情况访问、定位和传感器权限。不截图、不 OCR、不使用 WakeLock、不定时拉起进程。

使用界面事件触发并合并扫描，至少间隔 250 ms；常规遍历最多 180 个节点，另以最多4次系统文字查询保留最多32个补充候选。因操作冷却而延后的候选会在冷却结束后重新核对当前窗口，不持续轮询。屏幕关闭/锁定时停止。低功耗是实现策略，不能代替小米真机的电量测量。大量动态界面与启用弹窗/提示匹配的应用仍会产生处理开销。

屏幕文字仅用于当次内存匹配；本地数据库只记录包名、动作类别、规则名及时间。最近明细最多 300 条，界面展示最近 30 条；每日累计保留至手工清空。导出使用系统文件选择器。

## 构建

项目可直接用 Android Studio 打开。配置为 Java 17、AGP 8.5.0、Gradle 8.7、compile/target SDK 35、min SDK 26。Android 17 运行兼容性以实际测试记录为准，target SDK 35 不等于仅支持 Android 15。

Windows（已有 SDK 与依赖缓存）：

```powershell
.\scripts\build.ps1 -Test
```

可用 `-JavaHome` 与 `-AndroidSdk` 指定本机路径。脚本默认离线，使用本机 Build Tools 34.0.0 的 aapt2；全新环境须在 Android Studio 安装 SDK 35、Build Tools 34.0.0，并先联网同步 Gradle 依赖。其他平台可配置 `local.properties` 后运行 `./gradlew assembleDebug`。

APK：`deliverables/Wang-Cleaner-1.03-debug.apk`（构建源文件为 `app/build/outputs/apk/debug/app-debug.apk`）。独立测试页面：`fixture/build/outputs/apk/debug/fixture-debug.apk`。

```powershell
.\scripts\test-core.ps1 -JavaHome '你的JDK目录'
.\scripts\test-device.ps1
```

设备测试仅允许模拟器，会修改测试安装的王清理配置和统计，不能直接用于个人真机数据。最终验证范围见 [验证记录](docs/VERIFICATION.md)。

## 规则

参考 [示例规则](examples/rules-v1.json)。导入会替换本地规则和返回组合，验证失败保留旧配置；不会自动开启应用开关。

对同一包名和类型，只要存在本地规则，就只使用其已启用且匹配的规则，不回退内置规则。开屏和打开提示仍要求安全文字和小型按钮。新增 `kind: "popup"` 必须同时提供精确 `activity` 和 `context`，再以 `text` 或 `viewId` 定位小型按钮；仅用可信规则，否则错误规则可能点击正常按钮。示例中的测试包规则不是对真实 APP 的适配声明。

若仍无效，在设置中开始两分钟诊断，切换到目标 APP 复现，再返回查看并复制报告。统计为0只能说明没有记录成功动作；诊断用于区分事件缺失、窗口不一致、无候选、规则不匹配和点击失败。真实 APP 规则仍需结合具体界面验证。

`returns` 的 `enabled` 默认 false。示例返回组合也默认关闭。自定义 `activity` 是完整 Activity 类名，`viewId` 必须属于该包，`text` 与 `context` 是精确文本或节点描述。

本仓库不含商店发布签名；发布前需配置自己的签名、真机适配和所选商店的无障碍用途审核。
